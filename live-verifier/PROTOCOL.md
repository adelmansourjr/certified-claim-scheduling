# Timing a trained factuality checker

## Question

Can exact feature-level certificates reduce measured CPU work beyond parent-level short-circuiting, with no change to a fitted verifier's predictions? The preceding study scheduled fixed annotation verdicts and measured proxy costs. This follow-up checks actual predictions from a learned checker and times the running CPU pipeline. It uses the same official WiCE holdout, so this is a new outcome and verifier, not an independent sample of the prior corpus.

Ye, Santos-Rodriguez and Simpson decompose claims into reading-comprehension checks. This study starts with WiCE's released subclaims rather than generating them. It uses a linear verifier with evidence-matching features rather than the paper's language model. WiCE partially supported or unsupported annotations count as false for the strict fully-supported endpoint.

## Split and inputs

Use the same pinned train, development and test files as the parent project. Use only 2–8 subclaim parents for verifier training, model selection and assessment. In development and test, exclude parents sharing any normalized article title, evidence fingerprint, or surrounding context with earlier splits, following the parent implementation. The parent's exact filtering implementation also excludes matching empty contexts. Resample connected document/article/context groups, not individual subclaims. No supporting-sentence annotations, verdicts or other labels enter the features. Compute inverse document frequency for sentence retrieval weights from training documents alone. No LLM, downloaded model, large dependency, or model cache is needed.

For each document, tokenize up to 160 words of each evidence line and build a reusable lexical postings index. Truncate text claims to 64 words. Retrieve up to five lines by inverse-document-frequency coverage. In a zero-overlap case the earliest line provides the sole candidate. The same ten inexpensive features and three six-feature blocks comprise each verifier: exact lexical compatibility and numeric cues, sequence alignment, character-trigram fuzzy matching, and local-context coverage. Heavy blocks are individually computed on demand. No manually selected or labeled evidence is supplied. A ridge logistic model fits the full feature vector and a separate cheap model estimates verification priority. The primary full-verifier regularization grid is {.001,.01,.1}; select by balanced parent accuracy at the development conjunction threshold. Sweep logit cuts from -1.5 to +0.5 in steps of 0.05 with ties based on threshold proximity to zero and then smaller regularization. This is a lightweight baseline in factuality checking. Its errors matter, even where prediction preservation is guaranteed.

## Comparators and endpoint

- Exhaustive same verified prediction for all atoms.
- Original-order parent short-circuiting with lazy atom preparation, evaluating all three blocks for executed atoms.
- Lexical-router short-circuiting using the cheap model and the same full blocks.
- Strong comparator chosen by measured complete development CPU time among original, lexical and cost orderings. Lexical ordering places predicted least-supported first. Cost order uses claim length times retrieved-line count as a cheap estimate. The chosen order evaluates all blocks for all executed atoms and reuses a shared evidence index, deterministic character cache and precompiled scoring components.
- Box certificate ablation uses the same parent ordering and block order as the tighter certificate, but bounds every remaining feature independently in [0,1].
- Certified short-circuiting uses the same parent order and row cache as the strongest comparator. At every partial score, it bounds the uncomputed blocks and stops only when the frozen binary answer is determined. Choose the order of blocks from the six permutations on development CPU time. The same chosen feature computation order is used by every test method that performs all those computations.

The primary comparison is the ratio of sums of per-parent median CPU durations versus the development-selected strong comparator. Rebuild the document index per run, include routing and feature computation, and randomize method order within each of three paired repeats with seed 206753. This is a warmed Python process with a fixed-size character-level cache. The document index is cold on the primary comparison. A separate comparison reuses the document index to describe deployment with preprocessed text. Report all method costs, mean check counts, complete feature evaluations, prediction agreement, parent accuracy, balanced accuracy and prevalence. Secondary long-document stratum uses the 80th percentile of line counts defined on development, fixed before test. Report 5,000 paired block bootstraps as descriptive intervals over fixed-WiCE cases and one CPU setup. Timing positivity requires ratio reduction of at least 5%, lower paired interval above zero, and all identical decisions. Report actual failures. Do not interpret timing as an LLM gain, GPU/token saving, deployment budget or time estimate on all hardware.

## Proof

Every expensive block consists of two nonincreasing top-three triples in [0,1]. Each triple is a convex combination of the four prefix vertices (000, 100, 110, 111), with mixture weights given by consecutive differences and the complement of its first value. The signed dot product is therefore bounded by the minimum and maximum ordered prefix sums of the fitted weights. Add these bounds over the uncomputed triples, and add the exact partial margin. If the lower end exceeds zero the complete model must return support. If the upper end is below zero it must return not fully supported. Use 1e-9 slack and fall back to computing all stages near the boundary. Checking parents in any order therefore reproduces the conjunction of the frozen outputs. This is a worst-case certificate for the defined classifier. It cannot establish that any automatic verdict agrees with the underlying annotation. Ordered-triple bounds can be much tighter than bounding every feature independently. Prior branch-and-bound ideas are established, so we claim a concrete implementation and measured trade-off rather than a new class of inference algorithms.
